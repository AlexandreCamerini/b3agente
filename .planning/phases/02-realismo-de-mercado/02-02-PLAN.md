<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cliente não autenticado → `/api/market/status` | primeira rota do produto consumida ANTES do login (D-08) |
| corpo da requisição → decisão "mercado fechado" | entrada não confiável tentando escolher o regime de execução da ordem |
| token de sessão → ordem pendente | id de ordem no path pode apontar para recurso de outra conta |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-07 | Information Disclosure | reserva de caixa no escopo anônimo | mitigate | `/api/buy` e `/api/sell` respondem 401 quando `scope is None` E o mercado está fechado — o balde kv anônimo é compartilhado entre todos os anônimos (`db._scoped` devolve a chave crua sem escopo) |
| T-02-08 | Information Disclosure | `GET /api/market/status` | mitigate | rota declarada SEM `Depends(current_scope)`/`require_user`; payload restrito a 6 chaves de calendário; teste trava o conjunto de chaves e a igualdade com/sem token |
| T-02-09 | Elevation of Privilege | `DELETE /api/orders/pending/{id}` (IDOR) | mitigate | `cancelar` recebe `user_id=scope` e só varre a lista daquele escopo; id de outra conta resulta em 404; teste com duas contas |
| T-02-10 | Tampering | cliente forçando regime pendente durante o pregão | mitigate | o booleano vem só de `pregao.in_market_hours()`; nenhum campo do corpo é lido para isso; teste envia `{"pendente": true}` e assere execução imediata |
| T-02-11 | Spoofing | host gated recebendo status de mercado | accept | `/api/market` entra na allowlist deliberadamente: é dado público de calendário da B3, sem valor para atacante e necessário para a tela de login funcionar |
| T-02-12 | Denial of Service | rota pública sem rate limit | accept | resposta é O(1), sem I/O de rede e sem consulta ao banco; mesmo perfil de custo do `/api/health` já público |
| T-02-SC | Tampering | instalação de pacote npm/pip/cargo | accept | nenhuma dependência nova neste plano |
</threat_model>
