# Phase 21 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** this is a removal/consolidation phase, not an exploration
phase (`21-CONTEXT.md`, `<specifics>`: "Não é uma fase de exploração de
design — é remoção de duplicação e consolidação dentro do vocabulário visual
já existente"). No new color, no new spacing scale, no new component
library. Every value below is either a literal already shipped in
production or a Fase 20 constant (`numBody`/`numMicro`, `card`, `kicker`,
`MONO`) this phase is the first real consumer of, per `20-CONTEXT.md`'s
explicit deferral to Fase 21/22.

**Line numbers verified by direct read on 2026-09-05, NOT `21-CONTEXT.md`'s
estimates** — they drifted since the context doc was written (e.g. the
Portfólio `<CapitalCurve>` call site moved from the estimated `~8974` to
the actual `9027`; `EvolucaoScreen`'s from `~1976` to `2029`). Re-verify with
a fresh `grep -n "<CapitalCurve"` immediately before editing — this file's
line numbers can drift again between research and execution if another
phase's worktree touches `App.jsx` first.

## Spacing Scale

No new spacing scale. This phase reuses two already-established spacing
patterns byte-for-byte:

| Token | Value | Usage in this phase |
|-------|-------|-------|
| Card padding | `"16px 18px"` | Consolidated Portfólio card (DEDUP-03) — exact match of `EvolucaoScreen`'s "RESUMO DO DIA" card padding (`App.jsx:1974`), per `21-CONTEXT.md`'s "usar o card de Resumo do Dia como referência byte a byte de espaçamento." |
| Grid gap | `"16px 18px"` (row-gap 16px, column-gap 18px) | Consolidated Portfólio card's internal 2×2 grid — 16px is the 8-point-scale value; 18px matches the horizontal gap already used between "RESUMO DO DIA"'s three stat blocks (`App.jsx:1976`, `gap:"18px"`). Using a shorthand `gap:"16px 18px"` keeps the vertical rhythm on-scale while the horizontal gap stays visually consistent with its direct sibling screen. |
| Outer vertical margin | `"16px 0 18px"` | Preserve the exact margin the 4-card grid currently uses (`App.jsx:4358`) around the new single consolidated card — no change to the screen's vertical rhythm above/below this element. |

Exceptions: none beyond the above (both are direct reuses of existing
values, not new scale entries).

## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Card label (kicker) | 10px | 400 (inherits `kicker` — no explicit weight set, renders regular) | default | Consolidated Portfólio card's 4 cell labels — reuse the shared `kicker` constant (`App.jsx:293`) verbatim, exactly as "RESUMO DO DIA" already does at its own cell labels (`App.jsx:1977-1979`, `<div style={kicker}>...`). Do NOT invent a new label style. |
| Card value (primary) | 18px (`numBody`) | 700 (`numBody`) | not specified by `numBody` — inherit default | Consolidated Portfólio card's 4 primary values — first real production consumer of `numBody` besides `Topbar` (Fase 20 deferred this exact migration to Fase 21/22). | Card value (secondary) | 13px (`numMicro`) | 600 (`numMicro`) | not specified — inherit default | "Resultado aberto" cell's existing `pct(openPct)` sub-line — first production consumer of `numMicro`. Combine: `{...numMicro, fontFamily: MONO, color: subColor}`. |

**Why `numBody` here, not `numHero`:** the current 4 separate KPI cards
already render their primary value at `fontSize:"19px", fontWeight:600`
(`App.jsx:4343`, inside the `kpi()` helper) — closest to `numBody` (18px/700)
in the named scale, not `numHero` (34px/700, reserved for a screen's single
headline number — already used conceptually by `CapitalCurve`'s own
`money(patr)` at 27px, which this phase does not touch). Four side-by-side
numbers in a 2-column grid at 34px would not fit inside a 720px-capped
content column on a 375px viewport without wrapping — `numBody` is the
correct scale tier for this density, matching `21-CONTEXT.md`'s own framing
("mesmo padrão visual/densidade de 'RESUMO DO DIA'", whose values render at
17px, the closest existing precedent to `numBody`'s 18px).

**Why `kicker` for the label, not `numMicro`:** `21-CONTEXT.md` offered
both as options ("numMicro pro rótulo — ou manter o rótulo no estilo
`kicker` já existente"). `kicker` is the exact style "RESUMO DO DIA" already
uses for its own cell labels (`App.jsx:1977`, `<div style={kicker}>CARTEIRA
NO DIA</div>`) — reusing it is the literal byte-exact match `21-CONTEXT.md`
asks for. `numMicro` is reserved by this spec for the secondary VALUE line
(pct sub-value), giving it a real consumer instead of leaving it unused
after this phase, consistent with Fase 20's stated intent that Fase 21/22
give each constant a production call site.

### FIX-03 — "poucos dias" placeholder for `CapitalCurve`

**Gate on `ec.days`, not on `data.length` or `curve.length`.** Traced
through `finance.js:equityCurve` (`App.jsx:1734`, `finance.js:167-213`):
`ec.days = series.length` — the count of raw persisted equity snapshots,
which is exactly what `21-CONTEXT.md`'s prose calls "histórico de
patrimônio" and what the existing "DIAS REGISTRADOS" stat already displays
(`App.jsx:1841`, `stat("DIAS REGISTRADOS", String(ec.days))`). This is the
correct, already-user-facing variable to gate on — not `curve.length`
(which varies by ±1 depending on whether the live patrimônio replaces or
appends to today's snapshot, an implementation accident unrelated to "how
many days of data exist").

**Empirical confirmation of the degenerate case:** with `ec.days === 1` and
the one snapshot dated today, `plot` collapses to a single live value
(`finance.js:191-199`, the `last.data === todayYmd` replace branch), giving
`curve = [base, livePatr]` — exactly 2 points, `pctCarteira.length === 2`,
rendering one straight diagonal segment with no shape (`App.jsx:1770-1774`:
`min`/`max` come from only 2 values, `span` is just their difference — a
single-slope line, not a "curve"). This is the literal "caixa vazia com
escala degenerada" the requirement names. With `ec.days === 1` dated
yesterday (not today), `plot` gets 2 entries (snapshot + live) giving 3
total points — marginally less degenerate but still not a meaningful shape.
Both sub-cases are covered uniformly by gating on `ec.days`, so implementers
do not need to special-case same-day vs. prior-day.

**Threshold: `ec.days < 3` → placeholder (of which `ec.days === 0` keeps
today's exact copy; `ec.days` 1 or 2 gets new copy). `ec.days >= 3` → draws
the real curve, unchanged.** This matches the copy `21-CONTEXT.md` itself
proposes ("a curva aparece a partir do 3º dia") and the already-visible
"DIAS REGISTRADOS" stat semantics.

Implementation (`App.jsx:1736`, `CapitalCurve`):
```jsx
const hasSeries = ec.days >= 3;       // was: ec.days >= 1
const poucosDias = ec.days >= 1 && ec.days < 3;
```
The `ibov` benchmark-fetch `useEffect` (`App.jsx:1750-1758`) already keys
off `hasSeries` — no separate change needed there; delaying the Ibovespa
fetch until day 3 is the correct side effect (no point comparing a
benchmark against a curve that isn't drawn).

Render branch (`App.jsx:1836-1854`), add the new `poucosDias` case between
the existing two:
```jsx
{hasSeries ? (
  <> {/* unchanged curve + stats block */} </>
) : poucosDias ? (
  <div style={{ fontSize: "11.5px", color: T.textFaint, marginTop: "10px", lineHeight: 1.5 }}>
    {cp.curvaPoucosDias(ec.days)}
  </div>
) : (
  <div style={{ fontSize: "11.5px", color: T.textFaint, marginTop: "10px", lineHeight: 1.5 }}>
    Sua curva começa amanhã. Volte para vê-la crescer — cada dia que você abrir o app vira um ponto aqui.
  </div>
)}
```
Reuse the EXACT same wrapper style as the existing "zero" placeholder
(`fontSize:"11.5px", color:T.textFaint, marginTop:"10px", lineHeight:1.5`)
— same visual family, per `21-CONTEXT.md`'s explicit instruction ("mesma
família visual do placeholder de 0 pontos já existente"). Never render the
SVG (`<svg viewBox="0 0 300 92">...`) for `ec.days < 3` — both placeholder
branches skip it entirely (the chart's outer bordered container at
`App.jsx:1816` still renders as an empty frame with the dashed
"no-data-yet" squiggle path already used for `!hasSeries`, unchanged —
`21-CONTEXT.md` only asks to change the text/copy for the 1-2 case, not to
remove the existing dashed-squiggle visual, which already communicates
"not enough data" wordlessly and is shared by both empty-ish states).

`CapitalCurve` must destructure `cp` from `ctx` to reach the new copy key:
change `const { data, quotes } = ctx;` (`App.jsx:1729`) to
`const { data, quotes, cp } = ctx;` — `ctx.cp` already exists (confirmed:
`App.jsx:8760` includes `cp` in the `ctx` object built by `App()`), so this
is a zero-risk destructure addition, no prop-drilling change needed upstream.

### New copy key: `curvaPoucosDias`

Placement decision (resolves `21-CONTEXT.md`'s open question — "tom
professor/mesa conforme o modo... senão, uma string nova em copy.js, nunca
hardcoded"): add as an inline function inside BOTH `COPY.estudo` and
`COPY.operador` in `web/src/copy.js`, mirroring the existing
`saudacao`/`resumoDia` pattern (inline arrow functions living directly in
the per-mode dictionary, `copy.js:26-30`) — not a standalone wrapper export
like `historicoTxt`/`entradaAutoTxt`, because those wrap extra `estado`
branching logic this text doesn't need; a plain per-mode function with
pluralization is the simplest correct match to existing precedent.

**Why it needs a key in both dictionaries, unlike the sibling "0 pontos"
placeholder:** `copy.js`'s own header states a guardian test compares the
key SETS of `COPY.estudo`/`COPY.operador` — adding a key to only one mode
would fail that guardian. The existing "0 pontos" text
(`App.jsx:1852`) predates `copy.js` and is a known, pre-existing exception
to the file's stated convention, not a pattern to copy forward; `21-
CONTEXT.md` explicitly instructs new text to follow the convention instead
("nunca hardcoded... nunca string solta hardcoded no componente").

**Content — same tone in both modes is acceptable** (this is a factual
data-availability statement, not a decision/recommendation framing where
Estudo/Operador tone diverges elsewhere in the file):

```js
// in COPY.estudo and COPY.operador, same text both places (factual, not tone-bearing):
curvaPoucosDias: (dias) =>
  dias === 1
    ? "Só 1 dia registrado ainda — a curva aparece a partir do 3º dia."
    : "Só 2 dias registrados ainda — a curva aparece a partir do 3º dia.",
```

Call site: `cp.curvaPoucosDias(ec.days)` inside `CapitalCurve` (see
Structural Contract, FIX-03). `cp` here is already the resolved per-mode
dictionary (`ctx.cp` = `copyFor(appMode)` result, confirmed at
`App.jsx:7712`), so no `copyFor()` call is needed inside the component.
