# Phase 34 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase boundary reminder:** this is a reorg of existing rendering, not a
visual redesign (`34-CONTEXT.md` <domain>). This UI-SPEC therefore does NOT
introduce a new visual system — it extracts the actual values already in use
in `web/src/opcoes/*.jsx` and specifies where each existing block moves.
Every value below is sourced from the current codebase, not invented.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled React, inline `style={}` objects |

**Why no shadcn gate was run:** `components.json` and Tailwind config are
absent repo-wide, and the codebase has an established, 30+-phase-old design
token convention instead: a CSS-custom-property indirection (`VARKEY`/
`TOKENS`/`T` object at the top of every `web/src/opcoes/*.jsx` file) that
reads `var(--bgPanel)`, `var(--accent)`, etc. injected by `App.jsx` at
`:root` (Brand Book v2, theme × mode axes). Introducing shadcn now would be
an unrelated architecture change directly against `CLAUDE.md`'s "não
reescreva a aplicação sem necessidade" and this phase's own "reorganização
pura" framing. `Tool: none` is the correct, deliberate answer, not a skipped
step.

## Layout & Interaction Contract

This section is the load-bearing part of this UI-SPEC — it resolves what
`34-CONTEXT.md` locks (D-01..D-05) plus what it leaves implicit (cascade
placement, the ticker-chip selector, the shared-read block position), so the
planner/executor don't have to re-derive it from reading `OpcoesScreen.jsx`
cold.

### Top-level split

```
OpcoesScreen (subaba === "setups")
  cabecalho                                    ← ALWAYS visible, both modes (unchanged position)
  carregando / erro cascade (branches 1–2)      ← ALWAYS visible, both modes (see table below)
  ticker
    ? <Workspace/>
    : <Hub/>
```

`ticker ? Workspace : Hub` is the only new state read — reuses the existing
`ticker` `useState("")` in `OpcoesScreen.jsx` (D-01/D-02 of `34-CONTEXT.md`;
`FEATURES.md` lines 26-27). No new state, no router.

### Why `cabecalho` and the carregando/erro cascade sit ABOVE the hub/workspace conditional

Confirmed by reading `useOpcoesMcp.js`: `status` (which feeds `cabecalho`'s
pregão/fonte/frescor chip) is fetched on mount via a `ticker`-independent
`useEffect` (line ~154) — it is NOT gated by ticker selection. `erro =
escolherErroOpcoes(leitura.erro, status.erro)` and `carregando =
status.carregando || leitura.carregando` can therefore both be true or truthy
with **no ticker selected** (e.g. `status.erro` alone, MCP fora do ar,
before any ticker is chosen). If these two branches were nested inside the
workspace-only render path, an MCP-down state discovered before ticker
selection would be invisible in hub mode — a direct violation of **NAV-06**
("nenhum aviso crítico fica isolado numa seção fechada"). Contract:
`cabecalho` and cascade branches 1 (carregando) and 2 (erro) render once,
outside/above the `ticker ? Workspace : Hub` conditional, identical to their
current unconditional position in the JSX today. Do not duplicate them into
both branches — render once, above.

### Cascade branch placement (today's single if/else-if chain, split)

| Branch | Condition | Placement | Why |
|--------|-----------|-----------|-----|
| 1. Carregando | `status.carregando \|\| leitura.carregando` | Above split (both modes) | `status.carregando` fires pre-ticker |
| 2. Erro | `escolherErroOpcoes(leitura.erro, status.erro)` | Above split (both modes) | `status.erro` fires pre-ticker |
| 3a. Vazio — carteira vazia / escolher ativo | `semTicker` (includes `carteira.length === 0`) | Hub only | Both messages only make sense with no ticker selected |
| 3b. Vazio — sem candles / sem setups ainda | `!temLeitura && setups.length === 0` (ticker present) | Workspace only | Both messages require a ticker (`behavior`/`l` are ticker-scoped) |
| 4. Dados | `temLeitura` or `setups.length > 0` | Workspace only | `SecaoAnalisar`/`SecaoComparar`/`SecaoSetups`(criar) all require a ticker read |

Branches 1–2 keep the exact `if (carregando) ... else if (erro) ...`
short-circuit they have today (they are mutually exclusive with 3/4, so
"above the split" does not double-render — when 1 or 2 fires, neither hub
nor workspace content below it renders, same as today).

### Hub composition (D-04, fixed order — do not reorder)

```
Hub
  SecaoDescobrir            (frase-ponte + Bloco A + Bloco B, D-04 of Fase 33 — untouched, still one component)
  SecaoVigias               (Meus vigias — unchanged)
  seletor                   (ticker chip row — carteira.length > 0 only; ENTRY POINT into workspace)
  SecaoSetups (modo="lista") (Meus setups salvos — LISTING ONLY, D-01)
```

`SecaoDescobrir` is NOT split or touched — it is already one component from
Fase 33 (33-02) containing frase-ponte + Bloco A + Bloco B adjacent, which is
exactly what NAV-04 requires ("frase-ponte permanece fisicamente adjacente
ao Bloco B... nunca separada"). This phase does not re-derive that guarantee,
it inherits it unchanged.

### Ticker selector (`seletor`) — hub-only, not duplicated in workspace

`escolherTicker` is a **toggle**: tapping the currently-selected ticker's
chip again clears `ticker` (line ~292). If `seletor` also rendered inside
the workspace, it would create a *second* way back to the hub beside the
D-05 header button — contradicting NAV-03's "um único botão, sem histórico."
**Decision (resolves an ambiguity `34-CONTEXT.md` leaves implicit):**
`seletor` renders in the hub only. Once `ticker` is truthy, `seletor` is not
rendered; the workspace header's "Voltar" button (D-05) is the only path
back. This is a interaction-contract call within `34-CONTEXT.md`'s own
"Claude's Discretion" scope (workspace header styling was explicitly left
open) — flag for planner/plan-checker to confirm, not a blocker.

### Workspace composition (D-01, D-02, D-05, NAV-05)

```
Workspace (ticker truthy)
  WorkspaceHeader                    (NEW — D-05: ticker name + "Voltar" button, fixed at top)
  LastroDoAtivo                      (unchanged, ticker-gated today)
  LeituraInterna                     (unchanged, free technical read)
  blocoLeituraDoServico              (unchanged, paid-read invite — shown only pre-leitura)
  workspacePillRow                   (NEW — D-02: 3 tabs, reuses `subabas`/`seletor` pill style verbatim)
    "Analisar"    → SecaoAnalisar
    "Comparar"    → SecaoComparar   (only when temLeitura, unchanged gate)
    "Criar Setup" → SecaoSetups (modo="criar")   (creation block only, D-01)
```

`LastroDoAtivo` + `LeituraInterna` + `blocoLeituraDoServico` sit ABOVE the
3-tab pill row, shared by all three tabs — this is the mechanism that
satisfies **NAV-05** ("os três jobs continuam compartilhando uma única
leitura paga... trocar entre eles não paga de novo"): the paid read
(`leitura.dados`/`l`) is fetched once at the orchestrator level
(`useOpcoesMcp`) regardless of which of the 3 pill-row tabs is active, and
none of the three tab contents re-triggers it. Switching pill-row tabs is a
pure local `useState` (same mechanism as `subaba`/D-02), never a re-fetch.

### `SecaoSetups.jsx` partition (D-01, Claude's Discretion per CONTEXT)

Confirmed by reading the file: the list block and the create block are
already physically distinguishable inside `SecaoSetups.jsx` by their own
`Kicker` headings — `cp.opcoesSetupsTitulo` ("SETUPS GRAVADOS", the list) at
line ~56, and `cp.opcoesCriarTitulo` ("CRIAR UM SETUP", the creation form)
at line ~193. Recommended implementation shape (non-binding, per
CONTEXT.md's discretion note): keep one file, add a `modo: "lista" |
"criar"` prop that gates which of the two existing blocks renders — do not
duplicate the file or rename the internal Kicker copy.

### `.manchete` guardrail check (project_skill_context requirement)

Grepped `web/src/opcoes/*.jsx` for `.manchete`: it renders in exactly 4
files — `PropostaLastreada.jsx`, `CandidatoOpcao.jsx`,
`CuradoriaEstruturas.jsx`, `OportunidadesOpcoes.jsx` (the exact allowlist
`RENDERIZADORES_DE_MANCHETE` in `web/tests/test_opcoes_subabas_ui.mjs:244`).
None of these 4 files are directly relocated by this phase's hub/workspace
split: `CuradoriaEstruturas.jsx` and `OportunidadesOpcoes.jsx` are composed
inside `SecaoDescobrir.jsx`, which stays intact and entirely in the hub
(not split); `PropostaLastreada.jsx`/`CandidatoOpcao.jsx` belong to the
"Operar" sub-tab (`SubAbaOperar`), outside this phase's scope entirely
(this phase only restructures the "Setups" sub-tab). **No manchete
relocation happens in this phase** — the guardian test's allowlist does not
need to change. State this in the plan/SUMMARY so a future auditor doesn't
have to re-derive it.

## Spacing Scale

This phase reuses the app's established spacing values verbatim — it does
not introduce a new scale. Declared for reference (sourced from
`OpcoesScreen.jsx`/`uiOpcoes.jsx`, not the generic 8-point default):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/label gaps, `marginTop` on chip sub-lines |
| sm | 8px | Pill-row gap (`subabas`/`seletor`), chip padding-horizontal |
| sm+ | 10px | Chip padding-vertical, block margins (`margin: "10px 0 4px"`) |
| md | 12px | Box padding (`CAIXA`), border-radius on boxes |
| md+ | 14px | Box padding-horizontal, `cabecalho` border-radius, section `marginTop` |
| lg | 20px | Disclaimer block `marginTop` |

Exceptions: 10px and 14px are pre-existing, pervasive conventions in this
directory (not multiples of 8/4-clean in the strict sense but already
load-bearing across 30+ phases) — this reorg-only phase does not correct
them. The new `WorkspaceHeader` (D-05) MUST reuse the `cabecalho` box's
exact padding/radius (`padding: "12px 14px"`, `borderRadius: "14px"`) for
visual consistency — no new spacing value is introduced by this phase.

## Color

No new colors. Reuses the existing CSS-custom-property token indirection
(`T` object) — theme-agnostic by design (Brand Book v2, two independent
axes: theme × mode). Hex values are not declared here because they are
resolved at runtime by `App.jsx`'s `:root` injection, not by this file tree.

| Role | Token | Usage |
|------|-------|-------|
| Dominant surface | `T.bgBase` (via app shell) | Screen background, unchanged |
| Secondary surface | `T.bgPanel` | `cabecalho` box, `CAIXA` boxes, new `WorkspaceHeader` box, pill-row inactive state |
| Accent | `T.accent` / `T.accentTint10` | Active pill-row tab only (border/background/text) — same reserved-for list as today's `subabas`/`seletor` |
| Destructive | `T.negative` | Unchanged — `BotaoDesativar` (setup deactivation), not touched by this phase |

Accent reserved for: the active state of pill-row tabs (`subabas`,
`seletor`, and the new 3-tab workspace row) — border, tinted background,
and label color of whichever tab/chip is currently selected. Nothing new
gets accent in this phase; the `WorkspaceHeader`'s "Voltar" button
deliberately uses the neutral `BOTAO` style (`T.borderSubtle`/
`T.textSecondary`), not accent — it is a navigation action, not the
page's primary action.
