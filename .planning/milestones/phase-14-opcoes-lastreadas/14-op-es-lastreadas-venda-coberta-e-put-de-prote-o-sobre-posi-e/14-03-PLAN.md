`propor(underlying, chain, spot, plano, posicao, cash, modo, hoje) -> dict` devolvendo sempre `{"proposta": <dict|None>, "motivo": <str>}`, com `motivo` sendo uma das chaves de vocabulário do Task 1.

Ordem de avaliação (cada porta devolve imediatamente, com o motivo correspondente):
1. `chain` ausente ou `chain.get("providerStatus") != "ok"` → `"degradado"`.
2. `posicao` ausente ou `store.qty_livre(posicao) < 100` → `"sem_lastro"`.
3. Leitura técnica do ativo-lastro decide o TIPO:
   - `plano["decisao"] == "VENDER"` ou `plano["lado"] == "baixa"` → `put_protecao` (risco de queda sobre posição existente).
   - `plano["decisao"]` em `("AGUARDAR CONFIRMAÇÃO", "NÃO OPERAR")` ou `plano["lado"] == "neutro"` → `call_coberta` (sem alta a preservar, vender o upside gera prêmio).
   - `plano["decisao"] == "COMPRAR"` ou `plano["lado"] == "alta"` → `"sem_setup"` (vender call contra a alta que o motor está lendo trava justamente o movimento; comprar put contra alta é pagar proteção que o motor não pede). Registrar esse raciocínio como comentário no código.
   - `plano` ausente/vazio → `"sem_setup"`.
4. Prazo: `dias = _days_to(chain["expiration"])`; fora do intervalo fechado 15..60 → `"sem_vencimento_elegivel"`. (A cadeia carregada traz um vencimento só; escolher outro é papel da cadeia expansível, não da proposta.)
5. Contrato:
   - `call_coberta`: entre `chain["calls"]` com `strike > spot`, `lastPrice` numérico e `> 0`, e `liquidity_score(...)["score"] >= 40`, escolher o de MENOR strike (primeiro OTM).
   - `put_protecao`: entre `chain["puts"]` com `strike <= spot`, mesmo filtro de prêmio e liquidez, escolher o de MAIOR strike (proteção mais próxima do preço).
   - Nenhum candidato → `"sem_contrato_liquido"`.
6. Quantidade: `contratos = qty_livre(posicao) // 100`. Para `put_protecao`, limitar também por caixa: `contratos = min(contratos, int(cash // (100 * premio)))`; resultado 0 → `"caixa_insuficiente"`.
7. Proposta devolvida: `{"tipo", "contractSymbol", "optionType", "strike", "expiration", "diasParaVencimento", "contratos", "qtyAcoes", "premioUnitario", "premioTotal", "lastro": {"t", "qtyLivre"}, "liquidez": {"score", "label"}, "manchete", "didatica", "chips"}`.
   - `manchete` = `skill_ref.opcoes_lastreadas_txt(modo, tipo, ...)` — a frase do MODO recebido.
   - `didatica` = a mesma frase no modo `"educacional"`, sempre presente (o Estudo a usa como corpo; o Operador pode exibi-la como explicação secundária).
   - `chips` = lista de `{"k","v"}` com, no mínimo: `{"prazo", "{dias} dias"}`, `{"strike", "R$ {strike}"}`, `{"prêmio", "R$ {premioUnitario}"}`, `{"liquidez", label}`. Label de liquidez reusa os cortes já usados na UI (>=55 "NEGOCIÁVEL", >=30 "DIFÍCIL", senão "SEM MERCADO") — não inventar uma segunda escala.

`put_sem_lastro(option_positions, positions) -> list[str]`: devolve os `id` das posições com `side == "comprada"` e `lastro` cujo `lastro["qty"]` excede a quantidade atual da posição de ação correspondente (ou cuja posição sumiu). Valor DERIVADO na leitura — proibido persistir um campo espelho (mesma razão de `caixa_reservado` ser calculado, não guardado). Documentar no docstring que a put nunca é fechada automaticamente por isso: o motor sinaliza o estado, quem decide é o usuário (CLAUDE.md item 4 — nunca inventar ação).
