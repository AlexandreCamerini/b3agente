<objective>
Fazer o card de um setup inédito ENTRAR na lista com uma transição curta
(fade + subida de 8px, 200ms, ease-out), em vez de aparecer sem nenhum aviso
visual — nos dois lugares onde `AtivoCard` é renderizado em lista: a Watchlist
(`MercadoScreen`) e o Radar/Mesa (`RadarScreen`).

Purpose: MOTION-01. Hoje o app é binário — o card não existe, e no render
seguinte ele existe. Quando o Radar traz um setup novo, nada distingue
visualmente "isto acabou de chegar" de "isto já estava aqui". O movimento
aqui carrega informação; não é decoração.

Output: um `@keyframes` novo em `GlobalStyle()`, um mecanismo de "ticker já
visto NESTA montagem da lista" por tela (ref, não estado, não persistido), um
`className` condicional na raiz do `AtivoCard`, e um guardião novo que trava
as três coisas — inclusive a que é fácil quebrar sem perceber: um terceiro
bloco `@media (prefers-reduced-motion: reduce)`.

<mecanismo_de_visto>
O `23-CONTEXT.md` deixa o mecanismo exato à discrição do implementador. A
forma prescrita abaixo é obrigatória por causa do `StrictMode` (fato 2 de
`<estado_verificado_ao_vivo>`) — não é preferência de estilo.

**Forma prescrita** (uma instância por tela, dentro de `MercadoScreen` e
dentro de `RadarScreen`, nunca compartilhada entre elas — são listas
diferentes):

    // Fase 23 (MOTION-01): tickers já renderizados NESTA montagem da lista.
    // `useRef`, não `useState`: marcar "visto" não pode disparar re-render.
    // Não é persistido — "inédito" é relativo à sessão de visualização, e
    // trocar de aba DESMONTA a tela (App.jsx: `{tab === "..." && <...>}`),
    // zerando o conjunto de propósito.
    const vistosRef = useRef(new Set());
    const isNovo = (t) => !vistosRef.current.has(t);
    // O commit é EFEITO, nunca render: com React.StrictMode (main.jsx) o corpo
    // do componente roda 2x por render em dev; mutar o Set durante o render
    // faria a 2ª passada ler "já visto" e a animação nunca apareceria.
    useEffect(() => { <lista>.forEach((t) => vistosRef.current.add(t)); });

`<lista>` é `wl` em `MercadoScreen` e `resultsFiltrados.map((r) => r.ticker)`
em `RadarScreen`. O `useEffect` é **sem array de dependências de propósito**:
precisa rodar depois de TODA renderização, para que o conjunto reflita sempre
a renderização anterior. Não trocar por `useEffect(..., [])`.

**Por que a remoção da classe no render seguinte é segura:** o estado final do
keyframe (`opacity:1; transform:translateY(0)`) é idêntico ao estilo natural do
elemento. Se um re-render (tick de preço) tirar a classe no meio dos 200ms, a
animação é truncada — nunca deixa o card num estado quebrado, meio
transparente ou deslocado.

**Primeira pintura anima todos os cards da lista.** É o comportamento literal
descrito no `23-CONTEXT.md` ("comparar contra um Set de tickers já vistos" +
"reseta ao trocar de tela ou recarregar, o que é o comportamento correto"):
na primeira renderização não existe renderização anterior, o conjunto está
vazio, e todo card é inédito. A alternativa (semear o conjunto na primeira
passada para que só chegadas posteriores animem) **não deve ser implementada
neste plano** — ela contraria a decisão travada e, além disso, tornaria o
critério 1 do ROADMAP impossível de verificar sem provocar um setup novo ao
vivo. Se o Alex quiser essa variação depois, é decisão dele, não do executor.
</mecanismo_de_visto>
