```bash
if [ "${1:-}" = "--testes" ]; then
  say "Suítes do backend"
  bash scripts/test.sh || die "backend com falhas"
  say "Suítes web"
  RC=0
  for t in web/tests/*.mjs; do
    [ -e "$t" ] || continue
    if (cd web && node "${t#web/}" >/dev/null 2>&1); then ...OK... else ...[X]... RC=1; fi
  done
  exit "$RC"
fi
```
Dois problemas: (1) nenhum teste de `web/node_modules`; (2) `>/dev/null 2>&1`
engole a mensagem de erro, então `ERR_MODULE_NOT_FOUND` aparece como um `[X]`
mudo indistinguível de uma falha de asserção real.

`scripts/test.sh` já resolve o problema análogo do backend: procura o `.venv`
no clone principal via `git rev-parse --git-common-dir` porque em worktree o
venv local não existe (linhas 11-22). É o precedente de "o script resolve o
pré-requisito, não o humano".

`web/` tem `package.json` E `package-lock.json` versionados; `web/node_modules`
é gerado (gitignored). `web-admin/` é projeto npm independente e **não tem
suíte de teste** — `package.json` só declara `dev`/`build`/`preview`.
