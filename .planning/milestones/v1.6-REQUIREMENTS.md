## v1.6 Simplificação da aba Opções

**Defined:** 2026-09-19
**Core Value:** O usuário leigo sai do Modo Estudo entendendo de verdade como o mercado funciona — não decorou uma resposta, aprendeu o raciocínio — e só então tem acesso a automações do Modo Operador.

Base: pesquisa em `.planning/research/` (STACK/FEATURES/ARCHITECTURE/PITFALLS/SUMMARY), avaliação agentic UX escopada à aba Opções (sessão 2026-09-19), decisões confirmadas com o Alex via AskUserQuestion na mesma sessão.

## v1 Requirements — todos Done

Reorganizar a sub-aba "Setups" da aba Opções por job-to-be-done. Duas fases de risco crescente, confirmadas pelo Alex: primeiro extrair (sem tocar navegação), depois redesenhar a navegação.

### Extração (REORG) — Fase A: separar os 5 jobs sem mudar comportamento

- [x] **REORG-01**: Usuário vê os 5 jobs hoje misturados numa rolagem só — descobrir oportunidades cross-carteira (Blocos A+B), gerenciar vigias, analisar um ticker manualmente, comparar vencimentos, gerenciar/criar setups salvos — como seções fisicamente separadas em componentes próprios
- [x] **REORG-02**: Cada seção extraída preserva exatamente o comportamento, os dados e a ordem atuais — nenhuma funcionalidade nova, nenhuma removida
- [x] **REORG-03**: Nenhuma seção extraída instancia `useOpcoesMcp` de novo — todo dado chega por prop do orquestrador (`OpcoesScreen.jsx`)
- [x] **REORG-04**: `curadoriaAtiva` continua gateado por `tab` em `App.jsx`, nunca promovido a gate por seção/job — não pode reintroduzir o bug que a Fase 32 corrigiu (fetch pago amarrado à visita de uma tela)
- [x] **REORG-05**: Guardiões de teste que dependem de ordem/posição por arquivo são atualizados junto com a extração, sem afrouxar a garantia que cada um verifica
- [x] **REORG-06**: O guardrail CVM de manchete (hoje escopado só a `SubAbaOperar`) passa a cobrir qualquer seção nova que renderize `.manchete`
- [x] **REORG-07**: `top`/`meta` (seleção determinística do motor) permanecem imutáveis e passados por referência/índice a qualquer seção nova

### Navegação (NAV) — Fase B: hub + workspace

- [x] **NAV-01**: Sub-aba "Setups" abre em modo hub (frase-ponte + Bloco A + Bloco B + vigias + seletor de ativo) quando nenhum ticker está selecionado — **outcome ajustado**: "setups salvos" saiu do hub (D-01, emendado), "vigias" é a listagem cross-ticker que o critério pedia
- [x] **NAV-02**: Selecionar um ticker troca para modo workspace, sem os blocos de descoberta cross-carteira
- [x] **NAV-03**: Workspace tem um caminho de volta claro ao hub — um botão, sem breadcrumb nem histórico de navegação
- [x] **NAV-04**: A frase-ponte (mitigação regulatória D-05) permanece fisicamente adjacente ao Bloco B em qualquer novo arranjo do hub
- [x] **NAV-05**: Os jobs "analisar ticker", "comparar vencimentos" e "gerenciar setups salvos" continuam compartilhando uma única leitura paga — verificado ao vivo por medição de rede, não só por leitura de código
- [x] **NAV-06**: Estados de erro/degradado continuam visíveis independente de qual seção o usuário está olhando

## Out of Scope

| Feature | Reason |
|---------|--------|
| Router / URLs por job | App não usa router, decisão de arquitetura já travada na v1.5; navegação por estado (`ticker`) já resolve o drill-down sem precisar de rota |
| Terceiro nível de abas aninhadas dentro de "Setups" | App já está em 2 níveis (bottom nav → Setups/Operar); pesquisa converge em não passar disso |
| Layout multi-painel estilo terminal profissional (Bloomberg-like) | Usuário do Boris+ é leigo aprendendo, não trader profissional — contradiz o Core Value |
| Busca universal "ir para qualquer coisa" | Não existe hoje, não é reorganização — seria feature nova |
| Auto-refresh contínuo do hub | Conflita com a disciplina de frescor/staleness já estabelecida (princípio 3 do CLAUDE.md) |
| Cada job pagando a própria leitura MCP | Decidido com o Alex: manter uma leitura só para os 3 jobs, custo atual não deve subir |
| Fechar o backlog B2 (estado não sobrevive à troca de aba) | Dívida pré-existente (Fase 26, v1.4) — aberto por decisão explícita (D-03 da Fase 34), não fechado de passagem |
