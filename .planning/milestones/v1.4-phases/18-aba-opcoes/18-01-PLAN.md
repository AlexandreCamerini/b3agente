POSIÇÃO É OBRIGATÓRIA, não estética: o guardião
`test_opcoes_proposta_ui.mjs` usa `app.indexOf("store.optionsProposta(t, true)")`
— a PRIMEIRA ocorrência no arquivo precisa continuar sendo a de `AtivoCard`

plano — continua com o par de efeitos inline dele, intocado.

Contrato de retorno (os Planos 18-02 e 18-03 dependem literalmente destes
nomes de campo):

`useOpcoesPropostas(tickers)` → `{ propostas, carregando }`
- `propostas`: objeto indexado por ticker. Para cada ticker que já respondeu:
  `{ gate, proposta }` onde `gate` é a resposta crua de `store.optionsGate(t)`
  e `proposta` é a resposta crua de `store.optionsProposta(t, true)` (ou
  `null` se o gate reprovou ou a chamada falhou). Ticker que ainda não
  respondeu simplesmente não tem chave no objeto.
- `carregando`: `true` enquanto houver ao menos uma chamada em voo (gate ou
  proposta) para o conjunto atual de tickers; `false` quando tudo assentou.

Implementação — disciplina obrigatória, copiada de App.jsx:3213-3234:
- Um único `useEffect` cuja dependência é a CHAVE PRIMITIVA
  `const chave = (tickers || []).join(",")` — array como dependência recriaria
  o efeito a cada render de `CarteiraScreen`, disparando N requisições por
  render. Calcular `chave` fora do efeito e usar `[chave]` como array de deps.
- Dentro do efeito: `let alive = true;`, reset do estado
  (`setPropostas({})`, `setCarregando(true)` quando há tickers), e para cada
  ticker `t`: `store.optionsGate(t)` → no `.then`, se `!alive` retorna; grava
  o gate; se `gate && gate.liquida`, encadeia `store.optionsProposta(t, true)`
  e grava a proposta; senão grava `proposta: null`.
- TODA chamada termina em `.catch(() => { /* best-effort: sem gate/proposta o ticker só não aparece na tira */ })`
  — erro de rede vira ausência, nunca estado quebrado nem tile quebrado
  (mesma disciplina de App.jsx:3216 e :3231).
- `return () => { alive = false; };` como cleanup.
- `carregando` derivado de um contador de pendências decrementado em todos os
  caminhos (sucesso, gate reprovado e erro), nunca só no caminho feliz — senão
  a tira fica presa no texto de carregamento quando o backend falha.
- Atualização de estado sempre funcional (`setPropostas((m) => ({ ...m, [t]: ... }))`)
  — N respostas concorrentes escrevendo no mesmo objeto perderiam entradas com
  atualização não-funcional.
- `tickers` vazio: não dispara nada e devolve `{ propostas: {}, carregando: false }`.

Nomear a variável do gate dentro do hook como `gate` (não `opGate`) para deixar
explícito na leitura do fonte que este bloco não é o de `AtivoCard`.

Comentário de cabeçalho do hook, no padrão da casa (comentário carrega
história de decisão): citar Fase 18 Plano 01, NAV-01/NAV-02; explicar que UMA
busca por ticker serve as DUAS superfícies (tira agregada e detalhe dentro do
card de posição), e que não existe rota bulk por decisão explícita do
18-CONTEXT.md (fan-out por ticker é o mesmo precedente de custo do ADR-004).

Este plano NÃO consome o hook em lugar nenhum ainda — `CarteiraScreen` só
passa a chamá-lo no Plano 18-02. Uma função definida e ainda não usada é
esperado aqui; o build do Vite não reclama disso.
